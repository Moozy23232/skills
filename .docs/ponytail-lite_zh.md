# Ponytail Lite：精简开发模式

[English](ponytail-lite.md)

`ponytail-lite` 是一种需要显式开启的编码模式，用来构建足以完整解决真实需求的最小方案。

它采用一种“刻意偷懒的资深开发者”工作方式：先理解受影响的真实流程，再避开推测性功能、不必要的抽象、新增依赖，以及平台本身已经提供的代码。“偷懒”指提高效率，不是敷衍了事。

## 如何开启

这个 skill 永远不会自动启用，需要明确调用：

```text
请使用 $ponytail-lite 实现这个改动。
```

默认强度是 `full`。开启后，它会在当前会话后续的编码请求中持续生效。说“停止 ponytail-lite”或“恢复普通模式”即可关闭。

也可以直接指定强度：

```text
请使用 $ponytail-lite lite 添加这个接口。
请使用 $ponytail-lite ultra 精简这段实现。
```

## 它能帮你做什么

- 质疑目前并不需要存在的工作；
- 查找并复用代码库已有的 helper、类型和模式；
- 优先使用标准库、平台原生能力和已经安装的依赖；
- 用最少的必要文件和代码解决需求；
- 追踪所有调用方，在共享根因处一次修好 bug；
- 为非平凡逻辑保留一个最小可运行检查；
- 标注刻意采用的简化方案、能力上限和升级路径；
- 只针对可避免的复杂度和过度设计检查 diff。

这个 skill 只会在理解任务和真实代码路径之后精简方案。改动虽小但位置错误，依然不是好改动。

## 决策阶梯

它会按顺序检查，并停在第一个能够完整满足需求的方案：

1. 这个东西真的需要存在吗？
2. 代码库里已经有了吗？
3. 标准库能完成吗？
4. 平台有原生能力吗？
5. 已安装的依赖能解决吗？
6. 能否只用一行？
7. 如果都不行，最少需要写多少新代码？

如果两个方案都可行，它会选择更靠前、更简单的一个，但不会把这项检查本身变成漫长的调研。

## 强度级别

| 级别 | 行为 |
|---|---|
| `lite` | 完成你的要求，同时简短指出一个更省事的替代方案。 |
| `full` | 严格执行决策阶梯，交付最短的完整 diff；这是默认级别。 |
| `ultra` | 激进执行 YAGNI，优先删除，并质疑可以安全推迟的需求。 |

明确提出的要求仍然优先。如果你确认完整版确实必要，它会直接实现，不会反复争论是否应该缩小范围。

## 可以直接这样开始

精简地实现功能：

```text
请使用 $ponytail-lite 给这个请求路径增加缓存。追踪真实调用方，
复用已有实现，并留下一个最小可运行检查。
```

修复根因：

```text
请使用 $ponytail-lite full 修复这个校验问题。检查将要修改的函数的
所有调用方，在共享根因处修复，不要只给单一路径打补丁。
```

阻止推测性工作：

```text
请使用 $ponytail-lite ultra 处理这个方案。只实现目前必需的部分，
再用一句话说明剩余复杂度应在出现什么实际需求后加入。
```

恢复普通模式：

```text
停止 ponytail-lite，恢复普通模式。
```

## Review 模式

如果只想得到检查结果、不希望修改代码，可以调用一次性的 review 模式：

```text
请使用 $ponytail-lite review 检查这个 diff。
```

它只查找可以删除、可以换成标准库或原生能力、或者可以直接缩短的代码。每条发现都会给出文件与行号、简化类型和替代方案，最后估算可以减少的行数；如果已经足够精简，则输出 `Lean already. Ship.`。

这个模式刻意不检查正确性、安全性和性能；需要这些审查时，应另外明确提出。

## 它不会省掉什么

- 信任边界上的输入校验；
- 防止数据丢失的错误处理；
- 安全措施；
- 基础无障碍能力；
- 真实硬件所需的校准参数；
- 你明确要求的任何内容。

非平凡的分支、循环、解析器，以及金钱或安全相关路径，都会保留一个最小可运行检查。简单的一行代码不会为了形式完整而额外增加测试。

## 通常会怎样交付

完成改动后，它会保持交接简短：实现了什么、刻意省略了什么，以及什么情况下才值得加入被省略的复杂度。如果你明确要求解释、报告或详细导读，它仍会完整展开，而不会为了简短省略必要内容。
