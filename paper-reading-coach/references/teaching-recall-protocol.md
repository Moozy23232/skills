# Teaching and Recall Protocol

Use this protocol for guided reading, quizzes, question banks, misconception repair, or long-running review.

## Calibrate the Learner

Establish only what changes the teaching route:

- the learner’s goal: overview, implementation, derivation, reproduction, review, or presentation;
- current prerequisites;
- available time and desired depth;
- whether they prefer dialogue, notes, exercises, or code;
- whether answers should stay strictly within the paper.

Use a short diagnostic task when self-reported background is uncertain. Repair the smallest missing prerequisite immediately before it is needed.

## Define Observable Objectives

Write objectives as things the learner can do:

- explain a mechanism without undefined terms;
- derive or manipulate an equation;
- calculate a toy case;
- predict what happens when an assumption changes;
- read a figure and state its limits;
- compare the method with a baseline;
- identify an unsupported claim or missing control.

Avoid objectives such as “understand Section 3.”

## Layer Each Explanation

Present:

1. motivation and failure of the simpler approach;
2. plain-language intuition;
3. precise terms and notation;
4. worked example or derivation;
5. connection to the paper’s evidence;
6. boundary case, misconception, or analogy failure.

Stop after a major unit and request retrieval. Do not confuse a fluent explanation with learner mastery.

## Design Retrieval Questions

Cover multiple levels:

| Level | Learner action | Example form |
|---|---|---|
| 1 | Recall or identify | Define a symbol or locate a component |
| 2 | Apply or calculate | Compute a small case or trace a shape |
| 3 | Transfer or diagnose | Predict a changed setting or find an error |
| 4 | Challenge or synthesize | Construct a counterexample or defend against a reviewer |

For each important unit, prefer one strong question over many shallow ones. Include a real variant that changes data, assumptions, direction, or evaluation rather than merely rewording the prompt.

## Reveal Help Progressively

Use four stages:

1. point toward the relevant concept;
2. reveal the key relationship;
3. show the first concrete operation;
4. provide the complete solution with reasoning.

Record how much help was required. A correct answer after the final hint is evidence of exposure, not independent recall.

## Use Misconceptions as Teaching Material

Make every distractor correspond to a plausible error:

- confusing correlation with causality;
- swapping tensor axes or conditionals;
- ignoring normalization or a mask;
- treating a hyperparameter as a learned value;
- comparing different evaluation budgets;
- extending a theorem beyond its assumptions;
- assuming an absent ablation was performed.

After an error, name the misconception, repair it with the smallest counterexample, and ask a nearby variant.

## Run Interactive Review

1. Ask one question without displaying the answer.
2. Let the learner commit to an explanation or calculation.
3. Diagnose the first wrong step, not only the final result.
4. Give the smallest useful hint.
5. Request a corrected attempt.
6. Show a full solution only after the attempt or on request.
7. Ask a transfer question later in the session.

Use reviewer-style questions for major claims: “What alternative explanation survives?”, “Which missing experiment would change your confidence?”, and “Under which assumption does this derivation fail?”

## Schedule Review Conservatively

Only create a spaced-review system when the learner asks for persistent review.

- Add cards only for material already studied.
- Prioritize failed retrieval, high-importance claims, and recurring misconceptions.
- Delay well-recalled items and revisit weak items sooner.
- Include a daily cap so a large paper does not create an unmanageable first queue.
- Preserve the learner’s answer, hint usage, and misconception, not only a score.
- Allow export to a portable format.

Treat any scheduling algorithm as a convenience. Observed retrieval performance should override an automatic confidence estimate.

## Produce Useful Learning Artifacts

When requested, create the smallest suitable artifact:

- a paper map for orientation;
- a section note with locators and open questions;
- a symbol and shape table for equations;
- a claim-evidence ledger for critical reading;
- a question set with hints, answers, and variants;
- a review queue with difficulty evidence;
- a reading-status note for resuming later.

Keep learner annotations, source excerpts, explanations, and external context visibly distinct.
